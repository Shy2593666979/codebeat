## 额度与排程

### 智能工作时间优化（AWO）

本功能在现有任务执行器、额度读取、通知收件箱和 Windows 任务计划程序上扩展。入口保留在「设置 → 工作时间优化」。紧凑时间线位于「查看时间线与优化设置」上方，更多优化选项在原位置内展开，不新增页面。设置自动生效，验证失败的编辑不写入后台。

#### 设置与兼容

- 新配置的午休默认关闭，自动轻量请求默认关闭；旧配置已保存的午休选择保持不变。
- 上下班时间必填，支持跨午夜，不能相同。午休开启时，起止时间必填且须落在完整班次内；关闭时不解析、不参与计算，原值仍保留。
- `balanced` / `windows` / `save` 分别为智能均衡、最大窗口、节省额度。最短有效工作时间默认 60 分钟，可设置 15–300 分钟。
- `day_override` 按班次开始日期覆盖上下班和午休开关，用于临时加班、夜班或取消午休，不修改长期安排。跨午夜班次的工作日归属开始日期。
- SQLite 升级到版本 4，增加 `awo_runtime`、`awo_attempts`、`awo_activity`；不迁移用户数据路径，不改动已有任务或会话。

#### 算法

工作区间拆为一段或两段。候选首次时间在上班前不足五小时至上班时间之间按五分钟步长搜索；无午休且满足条件时，连续工作公式也作为候选参加评分。五小时始终连续流逝，不扣除午休。

按窗口与有效工作区间的交集计算有效分钟数。有效窗口达到用户的最短时长才计数。评分同时考虑窗口数量、短窗口惩罚、各窗口有效时长平方和、工作范围内的非工作空耗和额外请求数量；最大窗口模式提高窗口数量的权重。节省模式仅推荐，不额外请求。

候选评分的具体权重是工程启发式，不是对各平台额度恢复机制的承诺。时间线明确区分工作、午休、理论窗口和官方确认窗口。

#### 真实状态与重新规划

每次官方额度刷新都会保存并重算对应供应商的计划，设置改变、真实任务结束和执行器检查也会更新计划。已确认的五小时重置时间作为锚点，取消原定预热，从锚点到下一工作区间搜索后续候选时间，避免一律等到午休结束而破坏均衡。

例如 09:00–18:00 的初始建议为 06:00。官方数据确认用户已启动窗口，重置时间为 10:00 后，取消 06:00，后续建议改为 10:00、15:00。客户端进程启动、打开聊天窗口不会成为启动窗口的证据。快照过期时只保留上次确认的锚点用于推荐，执行许可关闭。

只有状态可用、官方来源、五小时窗口、有效百分比且观测不超过两分钟的快照用于执行判断。任何尚未到达的官方五小时重置时间均保守视为窗口活动，包括百分比四舍五入为零的情况。周额度耗尽也会阻止请求。

#### 执行保护

1. 优化总开关、自动轻量触发开关必须同时开启，供应商不能暂停，模式不能为节省额度。
2. 执行前重新读额度；健康和命令参数检查之后、实际发送之前再次读额度。不能确认旧窗口结束或已有活动窗口时取消请求。
3. 优先等待未来 15 分钟内的真实任务；已有任务正在执行时不竞争。
4. 计划只在目标时间后十分钟内仍有足够有效工作时间时执行。过期计划不会在开机后补发一串请求。
5. 发送前以 SQLite 原子语句持久化请求预约。同一供应商五小时内不再次预约，且同一计划最多预约一次，进程重启、失败和修改计划不会绕过限制。
6. 使用独立临时空目录，不恢复用户开发会话，不传入项目正文。Codex 必须支持临时会话、只读沙箱、结构化输出及忽略用户配置/规则的隔离参数。
7. 保存前后官方额度快照、重置时间、实际返回的 Token 计数、是否发送及结果。未返回的计数保持未知。仅收到成功结构化事件才视为请求成功。
8. 请求失败、无法确认窗口启动，或同一额度指标增加超过 **5 个百分点**，关闭未来自动轻量触发并记录提醒。该差值可能包含同时发生的用户请求，因此保守暂停；不承诺低于 1%。
9. 本功能没有任何使用重置卡的调用。

Claude Code 的候选命令已补齐 Haiku、单轮、禁工具与不持久化参数，但官方五小时窗口及模型适用性尚未实测确认，因此**自动轻量请求保持禁止**。不能拿 Codex 的测试结果作为 Claude Code 的验证结果。

#### Windows 与桌面客户端

每分钟检查任务本身禁止唤醒电脑；另行注册精确到推荐时间的一次性唤醒任务。当天最后一个推荐时间过去后，会为下一个有效工作日保留唤醒计划。额度变化、设置变化和真实任务执行后更新唤醒时间。关机不尝试开机；恢复运行后仍须经过过期和额度检查。

独立 CLI 优先，随后检测现有 Codex 桌面引擎及 MSIX 包中的原生组件。单独安装 ChatGPT 不代表存在可调用引擎；页面分别显示 ChatGPT 安装检测、引擎发现和实测状态，并提供现有官方安装/登录引导。普通 ChatGPT 对话不会作为 Codex 会话恢复。用户不需要 Rust SDK。

唤醒注册失败会在原生 stderr 留下 `AWO_WAKE` 记录；系统和硬件是否真正支持唤醒需要实机验证。未实现完成后自动恢复睡眠，避免打断用户。

#### 习惯统计

仅记录官方额度计数发生增长或窗口发生变化的观测时间，不读取对话正文，不把打开应用视为使用事件，排除本工具轻量请求。保留 30 天，最近 21 天内至少五个工作日观察到提前使用才提示考虑修改作息，绝不自动修改。当前夜班不生成提前工作提示，避免将班次结束后的用量误算为下一天提前工作。

### 按作息预启动额度窗口

此功能已升级为 [智能工作时间优化 AWO](#智能工作时间优化awo)，当前行为、配置、算法、执行保护及实测边界以该文档为准。

入口为「设置 → 工作时间优化」，时间线直接展示，优化选项在卡片内展开。午休默认关闭；支持跨午夜、三种优化模式和当天临时安排。总开关和自动轻量请求分别控制，默认不发送请求。官方额度无法确认或已有活动窗口时不进行无人值守触发；Claude Code 窗口规则实测通过前禁止自动轻量请求。

后台每分钟检查任务不唤醒设备，另行按推荐时间配置一次性唤醒任务。每次请求都先检查真实额度并持久化防重，执行后保存前后额度和实际 Token 计数；失败、窗口无法确认或异常消耗会暂停自动请求。本功能不使用重置卡。

原来的固定作息示例 10:00–20:00、午休 12:00–14:00 仍可得出 07:00 / 12:00 / 17:00，但这些是可被实际额度修正的建议，不是固定必执行时刻，也不是每五小时必然获得新额度的承诺。

### 额度读取失败后的重试

正常检测间隔仍由设置中的 5 / 10 / 30 / 60 分钟控制，默认 10 分钟。Codex 读取失败后，依次等待 5、15、30 秒，之后每次等待 60 秒继续尝试；没有固定重试次数上限。成功立即取消重试，下一正常检测周期接管旧周期，禁止跨周期堆积重试链。等待时间从上次请求完成后计算，请求自身仍有超时。

重试由桌面原生后台统一管理，主窗口隐藏到托盘后仍工作。定时、手动刷新共享每个提供商的请求锁，并发调用共享已完成的结果；恢复睡眠后只启动当前周期，不补发错过的每个请求。修改检测间隔会更新周期边界。

界面保留上次成功的额度、重置时间和重置卡数量，并显示“上次成功数据 · 自动重试中”。从未成功时显示未知和重试提示。后台成功通过事件更新首页、额度页与托盘，不重复弹出错误通知。重试期间重置卡操作暂时不可用，避免用陈旧状态发起操作；重试本身只读取额度，绝不调用模型请求或重置卡接口。

原始失败仍写入 `usage_snapshots` 并作为 `latest_usage` 返回，供 AWO 判断本次额度未验证、禁止无人值守执行。`latest_successful_usage` 仅供界面回退，不改变原数据时间戳或假装刚读取成功。额度查询和用户明确发起的重置卡操作共享锁，防止新旧结果交错。

### 每日 Token 消耗监控

首页原“本周额度趋势”已替换成“近 7 天 Token 消耗”。展示包含今天的连续七个本地日期。图表为单条平滑曲线：选择“全部工具”时使用两种工具每天的合计，选择 Codex 或 Claude Code 时显示该工具的每日用量。卡片移除总量、输入/输出汇总、工具颜色图例及底部说明，只保留标题、筛选、刷新和曲线日期；点击日期或标题仍可查看明细。额度页共用同一图表，可切换 7 / 14 / 30 天及工具。原顶部五小时/一周的剩余额度卡片保留原有口径。

曲线采用有界的三次插值，穿过真实每日计数，不因平滑处理生成超出相邻端点的新峰谷；长期日期标签减少密度，每天仍可点击。浅色和深色截图已检查：全部工具曲线、深色曲线。22 项前端测试与22 项浏览器测试通过，验证合计/单工具口径、单条曲线及删除指定文字；本轮打包。本轮 Rust 统计实现未改，沿用下方 40 项 Rust 验证结果。

图表显示本机可读取的实际用量计数，不从额度百分比推算 Token，也不等于账号跨设备总量或账单。缺少日志时显示未知及原因；读到历史记录但本期未发现用量时，显示本期无记录。读取失败、日志过大、格式变化、扫描未完成或缺少累计基数会标为不完整。

#### 数据来源与口径

- Codex：`CODEX_HOME/sessions` 与 `CODEX_HOME/archived_sessions`；未设置时使用用户目录下 `.codex`。
- Claude Code：`CLAUDE_CONFIG_DIR/projects`；未设置时使用用户目录下 `.claude/projects`，包含子代理日志。
- Codex 读取 `event_msg/token_count.info.total_token_usage`，按会话累计计数的增量入账。相同会话的重复事件与复制文件不重复计算，独立会话的相同数值分别计算；分叉会话创建前继承的历史事件跳过。缺失前序累计基数时只计入可确认的 `last_token_usage`，并提示不完整；计数回退不重复加入旧基数。
- Claude 读取 `assistant.message.usage`，以 `message.id` 去重；分段记录保留输出计数最完整的那一份快照，不累加重复快照，不累加结果消息的会话累计用量。
- 统一输入 = 普通输入 + 缓存输入。Claude 的输入需要加上 `cache_read_input_tokens` 与 `cache_creation_input_tokens`；Codex 的 `input_tokens` 已含缓存，缓存列为子集。总量 = 输入 + 输出，不再次加缓存或已经包含在输出内的推理 Token。
- 按事件时间转换为前端提供的 IANA 本地时区后归档。Claude 同一消息的多段记录以首次记录的日期归档。历史基数参与计算，但不直接计入当前日期。

[OpenAI 官方 App Server 文档](https://learn.chatgpt.com/docs/app-server)说明线程 Token 用量更新机制；本项目具体 JSONL 字段以本机真实日志结构验证，作为 best-effort 兼容读取，并不声明 JSONL 为稳定公开 API。[Claude 监控文档](https://code.claude.com/docs/en/monitoring-usage)明确缓存读取、写入与普通输入的关系；[Claude 用量跟踪文档](https://code.claude.com/docs/en/agent-sdk/cost-tracking)说明同一消息 ID 的分段记录需要去重。

#### 监控与资源控制

图表打开时读取，窗口可见时每 30 秒刷新，也可手动刷新。扫描在 Rust 后台线程执行；内存缓存文件偏移与用量元数据，下次只读追加内容，文件截断时重扫。正在写入的未完成行留到下次；不跟随链接，目录深度上限 20、每工具最多 20,000 个日志文件、单行 8 MiB、每轮读取预算 1 GiB / 约 5 秒。超限明确标记部分数据，后续刷新继续扫描。

缓存不保存会话正文或认证信息，不修改 CLI 日志，不额外发送模型请求。关闭应用后不继续扫描；重新打开时从现存日志恢复统计。删除本地日志后不能凭空恢复已删除用量。

## 会话

### 会话占用与任务设置

Codex 会话列表新增“使用中”，表示会话写入锁正被其他进程持有。创建任务左侧列表移除右箭头，只有占用项显示锁图标；占用项仍可选择。选中项加深底色，边框保持均匀，不再显示左侧色条。

选中的会话正在使用时，右侧显示“会话占用时”：

- 创建聊天分叉（默认）：执行时仍被占用，就复制源会话的历史，在独立分叉中发送任务提示词。
- 暂停任务：执行时仍被占用，以暂停状态结束此次执行，等待用户手动恢复，不启动模型执行 CLI。

锁状态每五秒刷新，选中和提交时重新检查，后台执行前再检查。若执行时已空闲，直接续聊源会话。无法确认状态时，表单阻止提交，执行器暂停任务。占用是瞬时状态，检查与 CLI 启动之间仍存在竞争窗口，最终由 Codex 的写入锁阻止并发写入；不会绕过或删除原始锁。

#### 检测方式

优先读取 `CODEX_HOME`，否则读取当前用户 `.codex`，检查 `thread-writer-locks/<会话 ID>.lock`。Windows 使用 `LockFileEx` 非阻塞尝试获取整文件独占锁，成功后立即释放。锁冲突代表占用；锁文件不存在或可以获取锁代表检查当时空闲；权限或其他错误代表未知。检测不创建锁文件，不读取会话内容，不恢复会话，不发出 AI 请求。锁目录属于本机 Codex 的实现细节，并非公开稳定的接口；未来版本需要继续验证兼容性。Claude Code 当前没有实现此项占用探测，不冒充已确认空闲。

分叉执行使用官方 `codex exec fork <SESSION_ID> -`，提示词通过 stdin 传入；空闲时使用 `exec resume`。CLI 参数和分叉机制参考 [OpenAI Docs：开发者命令](https://learn.chatgpt.com/docs/developer-commands?surface=cli) 与 [App Server 的会话分叉说明](https://learn.chatgpt.com/docs/app-server)。不在创建任务时提前生成分叉，也不自动重试已经提交的模型请求。

#### 固定任务设置

新建和编辑任务不再展示高级设置，提交以下配置：

- 执行权限：`full_access`。Codex 使用 `danger-full-access` 和 `approval_policy=never`；Claude Code 使用 `bypassPermissions` 及完整工具集。
- 完成后通知：开启，仍受应用通知总开关和成功/失败通知设置控制。
- 尝试从睡眠中唤醒：开启，实际结果仍受设备与电源策略限制。
- 错过执行时间：询问用户（`ask`），不会静默补执行。

旧任务数据中缺少分叉策略时按 `fork` 读取；已有任务未经编辑时仍按原请求中的权限与通知等字段执行。占用快照不作为执行依据。

### 会话记录分页

会话页和任务页共用 `src/components/PaginationBar.vue`，支持上一页/下一页、页码和每页 10/20/50 条，默认每页 10 条。筛选、搜索、页大小变化回到第一页；勾选可跨页保留，本页全选支持部分选中状态。会话页原有清空选择移到分页栏，移除最近使用/推荐区域，保留右键菜单、详情和续聊弹窗。列表直接在页面中展开，条数较多时由页面统一滚动，不再使用表格内部的纵向滚动框。

后端会话 API 返回游标，没有总数。因此按提供商并行遍历已有的元数据分页，按提供商+会话 ID 去重，读取结束后一次性提交并按更新时间合并排序，避免两种提供商响应时间不同引发先显示 Claude Code、随后换成 Codex 的闪动。不读取会话正文或发送 AI 请求。加载期间和读取不完整时显示“已加载”，完整读取后显示“共”；读取错误不隐藏已经读取的会话。重复游标停止并提示重试。

搜索/提供商变化即时使旧请求失效，防止旧数据在防抖期间或关闭页面后覆盖新结果。分页只影响当前表格展示，不改变具体会话及其对应的项目、工具或任务请求。

前端继续使用原来四份 400/500/600/700 WOFF2，文件哈希不变。Windows 通知只使用正文 Normal（400）和标题/按钮 SemiBold（600），所以安装包移除未使用的 Medium（500）和 Bold（700）TTF。源目录保留这些文件，生产分发由 `assets/fonts/source.json` 的 `native_faces` 明确列出，安装包检查拒绝意外带回未使用字重。

NSIS 原来已经使用 LZMA solid，继续使用相同无损算法，将字典从默认 8 MiB 调至 64 MiB。安装解压会使用更大的字典内存；应用日常运行的字体、排版与渲染不因这个安装压缩设置改变。依据：[NSIS SetCompressorDictSize](https://nsis.sourceforge.io/Reference/SetCompressorDictSize)。

验证：只提供两个字体的原生通知测试覆盖字体 URI、按钮、状态、安全文本和两秒计时；渲染及文件检查确认成功/失败/提醒三种通知逐像素相同，全部原字体文件 SHA-256 不变。打包日志见 font-size-package.txt，最终体积以产物核验为准。

网页可变字体、按字拆分等方法暂未采用。本轮优先移除未使用资源和改善无损安装压缩，保留现有渲染路径。
